## 3. JANK / RECOMPOSITION RISK (static)

- **Non-lazy list architecture (dominant pattern):** exactly **1 LazyColumn** in the whole app (ChatScreen.kt:163) — and it is the only keyed list (`items(messages, key = { it.id })`, ChatScreen:245; good). Everything else renders lists with `forEach` inside `Column.verticalScroll` — **47 verticalScroll sites in 44 files**. Top-3 heaviest lists sample: AdminPanelScreen (2,346 L; row forEach at :602/:1167/:1870/:1952/:2012), TournamentDetailsScreen (1,722 L), FriendsScreen (1,195 L; FriendCard forEach :419/:425, requests :481/:506). Every row is composed on screen open regardless of visibility; cost grows unboundedly with data — the classic low-end jank/memory amplifier (A7-03).
- **Countdown tick scope (A7-02):** TournamentDetailsScreen:134-142 — `var tick` lives in the top-level screen scope; `val nowMillis = remember(tick) {...}` reads it in the same scope ⇒ the **entire 1,722-line screen recomposes every 1 s** while open (participants list, stat rows, tabs, bottom bar all re-evaluated). Same pattern in HostDetailsScreen:101-111 (`nowTick` top-level, 1,182-line screen at 1 Hz). Web parity intent (setInterval) but Compose scope is the whole composable. Minimal fix: move the tick into a leaf `CountdownPill` composable that reads its own state.
- **Images (Coil 2.7.0):** 23 `AsyncImage` call sites; bounded-constraint cases are safe (TournamentDetails hero: fixed `height(200.dp)` box → Coil downsamples to measured size, :480-493). Caveat: AsyncImages inside non-lazy forEach lists (TournamentCard.kt:316 used by Home/Tournaments) decode eagerly for all composed (i.e., all) cards on open. No custom ImageLoader config anywhere (default memory cache ≈ 25% app RAM).
- **GPU-heavy decoration counts:** `blur()` ×8 (max radius 40.dp on 300.dp circles — LeaderboardScreen:124,133; Achievements ×2, Terms, Offline, HostSuccess, SuccessAnim), `shadowElevation` ×38, `graphicsLayer` ×2 (TeamCreationScreen). All static/decorative — acceptable but among the first things to degrade on weak GPUs.
- Auto-scroll `scrollToItem(messages.size)` on every message change (ChatScreen:121-125) — fine.
- Measured jank metrics: **NOT VERIFIED** (no device; needs JankStats/FrameTiming).

## Findings (template per TASK-006)

### A7-01 · Severity: MAJOR
- **Location:** `app/src/main/java/com/areenax/nativeapp/core/ui/AreenaxIcon.kt:44-54` (+ absent R-keep rule in `app/proguard-rules.pro`)
- **Steps to reproduce (static, no device needed):** build release (done) → parse `classes.dex` string table → `Lcom/areenax/nativeapp/R$drawable;` and every `ic_*` field-name string are absent (debug dex has 160+); only the template prefix `"ic_"` remains. `getField`/`Ljava/lang/reflect/Field;` ARE present — the reflective lookup survived, the class it reflects on did not.
- **Expected vs actual:** expected — `iconResId(name)` resolves `ic_<symbol>` in every build; actual — in the RELEASE build `R.drawable::class.java.getField(...)` throws (class stripped by R8; javac already inlined all direct `R.drawable.*` int constants so nothing keeps R$drawable) → `catch (_: Exception)` → **falls back to `R.drawable.ic_help`**. All **168 `AreenaxIcon` call sites** (data-driven icons: tasks, achievements, notifications, games, empty states, etc.) + **all BottomNav tab icons** (BottomNav.kt:82) render the help glyph in release; debug renders correctly (R$drawable present). The 53 directly-referenced drawables (e.g. SupportFab ic_support_agent, areenax_logo) are unaffected.
- **Root cause:** reflection over `R$drawable` fields with runtime-built names + no `-keep`/`-keepclassmembers` rule for R classes; R8 removes the (unused-after-constant-inlining) class; `shrinkResources` kept the drawable FILES (178/178 — resource stripping did NOT happen; the correctness risk is in code, not resources) — the inverse of the task's working hypothesis.
- **Proposed minimal fix:** replace reflection with a compile-time `when(name)` map of `R.drawable` constants (no keep rule needed, also faster), or add `-keepclassmembers class **.R$* { public static <fields>; }` to proguard-rules.pro. The when-map is preferred (also removes the HashMap cache and reflection latency).
- **Regression risk:** low — the map is exhaustive over SPEC/ICONS names; behavior identical to debug.
- **Evidence:** `audit/evidence/phase2/a7-size-r-survival-dex.log`, `a7-size-arsc-drawable-counts.log`. Cross-ref: A6 (shrink/keep rules), A3/A8 (visual checks — release-only so untestable without device), ICON-AUDIT (icon-name inventory).

### A7-02 · Severity: MAJOR
- **Location:** `TournamentDetailsScreen.kt:134-142`, `HostDetailsScreen.kt:101-111`
- **Steps to reproduce (static):** read tick state declaration + its read site — both in the top-level screen scope.
- **Expected vs actual:** expected — only the countdown pill updates per second; actual — `tick`/`nowTick` are read at the root of a 1,722/1,182-line composable ⇒ whole-screen recomposition at 1 Hz for as long as the screen is open (participants list included; on non-lazy Columns that re-runs every row's composable lambda).
- **Root cause:** tick state scoped to the screen instead of a leaf composable.
- **Proposed minimal fix:** extract a `CountdownPill(text = countdownText(...))`-style leaf composable that owns the 1 s ticker; screen body reads nothing ticking.
- **Regression risk:** low — countdown display semantics unchanged.
- **Evidence:** `a7-jank-static.log`.

### A7-03 · Severity: MAJOR
- **Location:** 44 files / 47 `.verticalScroll(` sites; heaviest: AdminPanelScreen:173/:1481, FriendsScreen:286, MyTournamentScreen:136, LeaderboardScreen:141, NotificationsScreen, AdminTournamentsScreen:238
- **Steps to reproduce (static):** `rg -c 'LazyColumn\(|LazyRow\(|LazyVerticalGrid\('` → only ChatScreen; `rg -c '\.verticalScroll\('` → 47.
- **Expected vs actual:** expected — long lists window their composition (LazyColumn + keys); actual — every row of every list is composed on open; cost scales with data size; on a 2 GB device this is the main scroll-jank + memory-growth risk (admin/leaderboard/friends/participants grow without bound server-side).
- **Root cause:** web-parity port (React renders lists inside a scrolling page) transplanted to Compose without the lazy-container translation, except ChatScreen.
- **Proposed minimal fix (fix phase):** convert the top offenders (Admin lists, Friends, My Tournaments, Leaderboard, Notifications) to `LazyColumn` with stable keys; keep exact web visual order.
- **Regression risk:** med — scroll-position/anchoring semantics change slightly; needs the (absent) device tests.
- **Evidence:** `a7-jank-static.log`.

### A7-04 · Severity: MINOR
- **Location:** `ChatScreen.kt:78,:112-118`; `Api.kt:239-242`
- **Steps to reproduce:** read the poll loop + endpoint declaration.
