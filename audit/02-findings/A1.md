## 3. Architecture Pattern

**Overall shape:** single-Activity, no-ViewModel, no-repository "web-port" architecture. The web panel's zustand store + module singletons are ported 1:1 into a `Application`-scoped **ServiceLocator** and a CompositionLocal dependency object. State is Compose-idiomatic but screen-local.

- **DI = ServiceLocator.** `AreenaxApplication` exposes 8 lazy singletons: `session`, `connectivity`, `navigator`, `toast`, `unread`, `api`, `env`, `baseAppUrl` (`AreenaxApplication.kt:32-66`). Cross-cutting wiring is imperative in `onCreate`: `ApiClient.onUnauthorized = { session.onSessionInvalid(); navigator.logout() }` (`AreenaxApplication.kt:72-75`) and a fire-and-forget `SettingsCache.get` warmup (`AreenaxApplication.kt:78-80`). There is no injection framework and no interface boundary — every collaborator is a concrete class/object (`ApiClient`, `SettingsCache` are `object`s: `ApiClient.kt:26`, `SettingsCache.kt:18`).
- **State management: zero ViewModels** (`rg -n 'ViewModel'` → 0 hits). State is:
  - `MutableStateFlow`/`StateFlow` in Application-scoped services: SessionManager token/user/unread/theme/hydrated (`SessionManager.kt:46-60`), navigator screen/params/stack/generation as Compose `mutableStateOf` (`AppNavigator.kt:26-41`), ConnectivityObserver `isOnline` (`ConnectivityObserver.kt:24-25`), ToastController queue (`ToastHost.kt:69`).
  - Screen-local `remember`/`mutableStateOf` — 706 `remember` hits and 59 `rememberSaveable` across the app; 68 `collectAsState` calls bridge the StateFlows into composables.
- **Screens get data by calling the API directly.** No repository/use-case layer exists (`rg -n 'Repository'` → 0 hits). 89 `env.api.` call-sites across 30+ files, always wrapped in the central `safeCall { }` helper (`ApiResult.kt:55-70`; 139 `safeCall` call-sites). Canonical pattern — `WalletScreen.kt:157-176`: `LaunchedEffect(Unit) { when (val res = safeCall { env.api.wallet() }) { Success → update state + session; Error/NetworkError → EmptyState data + destructive toast } }`.
- **Session/auth token storage: DataStore (plaintext).** One preferences file `"areena-app"` (`SessionManager.kt:40,220`); keys `token` + `user` (`SessionManager.kt:224-225`); hydration in `init` (`SessionManager.kt:64-73`); 401 wipe is synchronous in-memory + async on disk (`SessionManager.kt:197-217`). Same file also carries theme, pending-QR, pending-link and bank-selection keys (`SessionManager.kt:226-230`) — mirrors the web's localStorage/sessionStorage split.
- **Image loading:** Coil `AsyncImage` ×17 (banners, avatars, receipts — e.g. `ui/screens/main/HomeScreen.kt:288,503`, `core/ui/TournamentCard.kt:316`); bundled vector drawables via `painterResource`; QR **generation** via ZXing `QRCodeWriter().encode(...)` → Bitmap (`core/ui/QRCodeImage.kt:47`) and **scanning** via zxing-embedded `ScanContract` launcher (`core/ui/QrSheet.kt:60,282`).
- **Custom navigation system.** There is NO NavController/Navigation-Compose. Routes ARE the 46 string constants in `ScreenKeys` (`core/nav/ScreenKeys.kt:8-99`, "EXACT string constants from the web `Screen` union"). `AppNavigator` is a plain state machine — `currentScreen` + `currentParams` + back-stack `NavEntry` list capped at 25 + `generation` counter + `lastWasPush` (`AppNavigator.kt:21-61`); `navigate/replace/goBack/setAuth/logout/enforceAuthGate` mirror web `store.ts` semantics exactly (`AppNavigator.kt:9-20` KDoc). `AppNavHost` projects `navigator.currentScreen` onto composables through `AnimatedContent` with directional push/pop slide+fade (260 ms easeOut, `AppNavHost.kt:50-91`) and holds the registry (`AppNavHost.kt:98-164`); system back is a `BackHandler` except on `home`/`login` roots (`AppNavHost.kt:47,59-61`). Every screen receives one `NavEnv` (`core/nav/NavEnv.kt:29-40`) — navigator, session, unread, toast, connectivity, baseUrl, appContext, lazy `api` — supplied via `LocalNavEnv` CompositionLocal (`NavEnv.kt:88-99`) from `AppScaffold` (`MainActivity.kt:61-63` → `AppShell.kt:74,161`). Nav params are `Map<String, Any?>` (`NavEnv.kt:47`), consumed with `as?` casts in screens (e.g. `HostCreationScreen.kt:101-102`).

## 4. Request Lifecycle

Single entry point `ApiClient.create(baseUrl, sessionManager)` (`core/network/ApiClient.kt:39-54`):

1. **Base URL** comes from the string resource `app_base_url` (`AreenaxApplication.kt:66` ← `app/src/main/res/values/strings.xml:11`), normalized by appending `/api/` with a `require(...startsWith("http"))` guard (`ApiClient.kt:56-61`) — mirrors web `fetch("/api" + path)`.
2. **Interceptor chain** (`ApiClient.kt:41-46`), in order:
   - `AuthInterceptor` — adds `x-token: <token>` from `sessionManager.token` when present (`ApiClient.kt:65-75`).
   - `IdempotencyInterceptor` — fresh UUID v4 `Idempotency-Key` on every non-GET (`ApiClient.kt:78-88`).
   - `InFlightGuardInterceptor` — client-side double-submit guard: one in-flight mutation per `METHOD path`; second concurrent call throws `RequestInFlightException` pre-network (`ApiClient.kt:95-112`).
   - `UnauthorizedInterceptor` — on HTTP 401 invokes the `ApiClient.onUnauthorized` callback (set by the ServiceLocator) and still returns the response (`ApiClient.kt:114-123`; wiring at `AreenaxApplication.kt:72-75`).
3. **Serialization** — kotlinx-serialization converter over a shared tolerant `Json { ignoreUnknownKeys=true; explicitNulls=false; encodeDefaults=true }` (`ApiClient.kt:29-33`).
4. **Result mapping** — every call site wraps in `safeCall` (`ApiResult.kt:55-70`): `Success(data)` | `Error(message, code)` (HttpException → body parsed by `extractErrorMessage`, reading the JSON `error` field, fallback `"Request failed (<status>)"`, `ApiResult.kt:34-49`; in-flight → `Error(..., 409)`) | `NetworkError` (IOException/timeout/DNS, message default `"Network error. Please check your connection."`, `ApiResult.kt:21-24`). Screens branch on this sealed type and toast failures (e.g. `WalletScreen.kt:158-176`).
5. **No timeout/retry tuning** — the OkHttp builder sets only interceptors (`ApiClient.kt:41-46`); library defaults (10 s connect/read) apply. No retry/backoff anywhere.

## 7. FINDINGS

**F-1 · MAJOR — API base URL is a non-functional placeholder.** `app/src/main/res/values/strings.xml:11` ships `https://YOUR-AREENAX-DOMAIN.example.com`, and `AreenaxApplication.kt:66` feeds it to every request via `ApiClient.normalizeBaseUrl` (`ApiClient.kt:56-61` — the `require(startsWith("http"))` guard happily accepts it). Until the deployer edits STEP 1, every API call fails and surfaces as a `NetworkError` toast; nothing at build time warns or fails. This is the single deployment gate between "compiles" and "works"; recommend a startup assertion or build-config injection. (The README documents the manual step; the code does not enforce it.)

**F-2 · MAJOR — zero automated tests, zero test infrastructure.** `app/src/` contains only `main` (directory listing). No `test/` or `androidTest/` source sets, and no test dependencies exist in `gradle/libs.versions.toml` (no JUnit, no Robolectric, no Compose UI test, no MockWebServer). For a 35-KLOC financial-adjacent app (wallet flows, admin ops), every regression currently costs a manual APK run on a device — which has never happened (worklog Task 9: "NOT VERIFIED (no device/emulator)"). The singletons in F-3 are the main obstacle to adding tests later.

**F-3 · MAJOR — ServiceLocator "DI" + object singletons make the code untestable by construction.** All collaborators are concrete and Application-scoped: `AreenaxApplication.kt:32-66` lazily builds session/navigator/toast/unread/api/env with no interfaces; `ApiClient` and `SettingsCache` are global `object`s with mutable global state (`ApiClient.kt:26,36-37` `@Volatile var onUnauthorized`; `SettingsCache.kt:20-23` `@Volatile cached` + non-volatile `inflight`). Consequences: (a) no fake can be substituted for `Api` without Retrofit-on-OkHttp-MockWebServer; (b) `ApiClient.onUnauthorized` is process-global — any test mutating it leaks into the next; (c) `NavEnv` bundles everything, so a screen unit test needs the whole graph. This is a deliberate 1:1 web-port trade-off, but it directly causes F-2.

**F-4 · MAJOR — oversized "god" files.** AdminPanelScreen.kt 2,346 LOC (≈6.7% of the app in one file, containing reconcile/security/games/results/proofs sections plus its own coroutine launches), TournamentDetailsScreen.kt 1,722, FriendsScreen 1,195, HostDetailsScreen 1,181, HostCreationScreen 1,145, Models.kt 1,023 (ALL DTOs in one file — every API change ripples through it). Ten files exceed 680 LOC. Merge-conflict surface, review difficulty, and the F-5 hotspots all concentrate here.

**F-5 · MAJOR — unstructured concurrency in UI code.** 21 raw `CoroutineScope(Dispatchers.Main).launch { … }` calls in `ui/**` (list in metrics) create orphan scopes that are never cancelled when the composable leaves composition — work continues after navigation, mutating `remember` state of dead screens and leaking. Canonical example cluster: `AdminPanelScreen.kt:401,467,501,528,888,962,…` (12 sites). By contrast, data loading correctly uses `LaunchedEffect` (108 sites) and SessionManager/UnreadManager/SettingsCache each own a private `SupervisorJob` scope (`SessionManager.kt:42`, `UnreadManager.kt:23`, `SettingsCache.kt:25`) — acceptable for app-lifetime services, wrong for screen-triggered actions (they should use `rememberCoroutineScope` or the `LaunchedEffect` pattern).

**F-6 · MINOR — manifest/security posture.** `AndroidManifest.xml:4-6`: permissions are exactly INTERNET + CAMERA + ACCESS_NETWORK_STATE (record corrected in worklog Task 9; matches built APK). `android:allowBackup="true"` (`AndroidManifest.xml:16`) combined with plaintext token/user in DataStore (`SessionManager.kt:224-225`) means the session token can be extracted via adb backup / auto-cloud-backup on ≤SDK-30 devices — for a money app, prefer `allowBackup=false` or `dataExtractionRules` excluding the session file + EncryptedSharedPreferences/Keystore-wrapped storage. `MainActivity` is `exported=true` (required for a launcher), `singleTask`, portrait-locked, `adjustResize` (`AndroidManifest.xml:25-31`) — fine. `usesCleartextTraffic` is absent and there is **no** `res/xml/` network-security-config (res contains only drawable/font/values) → platform default (cleartext blocked on API 28+) applies; base URL is https, so TLS is effectively enforced. CAMERA is properly soft-failed via `uses-feature required=false` (`AndroidManifest.xml:10-12`) with the manual-UID fallback documented (`QrSheet.kt` manual entry).

**F-7 · MINOR — i18n is structurally impossible: 100% hardcoded UI strings.** `strings.xml` has 2 entries (`app_name`, `app_base_url`); `stringResource()` appears 0 times; 40 `Text("…")` literals plus 2,332 string literals across `ui/screens` (metrics §6). `resourceConfigurations += "en"` (`app/build.gradle.kts:18`) confirms English-only intent, but the TODO-state means any future locale (the web panel serves Arabic-adjacent markets — JazzCash/Easypaisa context) requires a full copy-extraction pass. **F-8 · MINOR — color tokens bypassed in screens.** 50 hex literals live in `ui/screens` and 5 in `core/ui` against 87 centralized in `core/theme/Tokens.kt`. Worst offenders: AboutScreen.kt (14), TeamCreationScreen.kt (6), OfflineScreen.kt (5). **F-9 · MINOR — copy-paste duplication patterns (3 concrete pairs).**

**F-11 · MINOR — error handling is consistent in shape, inconsistent in consequence; zero observability.** The canonical `safeCall → when → toast(Destructive)` pattern is followed everywhere (139 safeCall sites; good example `WalletScreen.kt:158-176`; combined-branch variant ×7), and 401/auto-logout is centralized (`ApiClient.kt:114-123` + `AreenaxApplication.kt:72-75`).
