**A8-01 · Severity: MAJOR**
- **Location:** `app/src/main/AndroidManifest.xml:25-36` (no `android:enableOnBackInvokedCallback`), `core/nav/AppNavHost.kt:59-61` (BackHandler), `gradle/libs.versions.toml:5-6` (activity-compose 1.9.3 / compose-bom 2024.12.01)
- **Steps to reproduce:** (static) grep manifest for `enableOnBackInvokedCallback` → absent; grep tree for `OnBackInvokedCallback|PredictiveBack` → 0 hits; observe `BackHandler(enabled = navigator.currentScreen !in BACK_ROOT_SCREENS) { navigator.goBack() }` wrapping every non-root screen. (runtime) on an Android 14+ gesture-nav device, start a back swipe from any non-root screen — NOT VERIFIED, no device.
- **Expected vs actual:** Expected: predictive back (system preview / back-to-home animation) available on Android 13+/14+ per platform guidance; Actual: app opts out at three layers — (1) manifest flag missing, (2) Compose `BackHandler` intercepts the gesture and runs `navigator.goBack()` only after the gesture commits, (3) activity-compose 1.9.3 predates the predictive-progress APIs (`PredictiveBackHandler`), so no progress callback even exists to wire up. Back from the roots (`home`, `login`) falls through to activity finish — also without predictive animation.
- **Root cause:** Custom in-memory navigator (web `store.ts` port) uses the legacy `BackHandler` interception model; predictive back was never enabled in the manifest.
- **Proposed minimal fix:** Two-step: (a) add `android:enableOnBackInvokedCallback="true"` to `<activity>` + upgrade activity-compose ≥1.10 / compose ≥1.8; (b) replace `BackHandler` with `PredictiveBackHandler` in AppNavHost.kt:59, driving `navigator.goBack()` on commit (optionally scrubbing the 260ms pop transition on progress). If the owner prefers no dependency bumps, consciously accept the opt-out and record it (A10 overlap: Android 16 pressure).
- **Regression risk: med** — the BackHandler→PredictiveBackHandler swap touches the single most-trafficked code path (system back on every screen); the flag itself is low-risk, the handler migration needs regression on back-from-every-screen (46 keys, 2 roots, offline pop logic AppShell.kt:121-129).
- **Evidence:** `a8-greps.log` E2, `a8-citations.md` S5.
