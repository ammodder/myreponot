## 0. DIRECTED SHRINK-CHECK (orchestrator suspicion: "resource shrinking may have STRIPPED dynamically-referenced icons")

**VERDICT: icons NOT stripped — SAFE on the resource side. The feared release failure exists anyway via a DIFFERENT mechanism (R8 R-class inlining breaks the reflection lookup), graded A6-01 BLOCKER below.**

Evidence chain (full logs in `audit/evidence/phase2/apk-scans/`):

1. **Resource tables are identical.** `aapt2 dump resources` unique drawable names: release = **178**, debug = **178**, set-difference = **0 stripped / 0 added** (`a6-shrink-check-drawables.log`). res/ file counts also identical (17 png + 183 xml each); release paths are merely obfuscated by `optimizeReleaseResources` (`res/-N.xml`), names in the table are intact.
2. **The shrinker kept every dynamic icon and then threw its own output away.** `app/build/outputs/mapping/release/resources.txt` marks **175** drawables reachable (160 `ic_*`, explicitly including dynamic-only ones: *"Marking drawable:ic_trophy:2130968729 … used because it matches string pool constant `ic_`"* — the `"ic_"` prefix constant in `AreenaxIcon.kt:40` saved them all), and its final line reads: **"Resource shrinking did not work (grew from 236171 to 237956); using original instead"** → the original, complete `resources.arsc` shipped.
3. **The REAL failure: R8 removed every `R$drawable` field, so `iconResId()`'s reflection can never succeed in release.** mapping.txt: `com.areenax.nativeapp.R$drawable -> Q1.f:`; usage.txt lists `public static int ic_trophy` (etc.) as **removed**; dexdump of release `classes.dex`: class `LQ1/f;` has **"Static fields —" (empty)**; the reflection site is compiled as `const-class v3, LQ1/f;` + `invoke-virtual … Class.getField` (dexdump :800665-:800666). The merged R8 configuration contains **no keep rule for R classes** (`rg 'R\$*' configuration.txt` = none; `proguard-rules.pro` has none either). Debug APK keeps the real `R$drawable` with fields (classes2.dex) → code works in debug only.
4. **Runtime consequence (release-as-built):** `AreenaxIcon.kt:48` `R.drawable::class.java.getField(name2)` throws `NoSuchFieldException` for **every** name → caught → `:51` returns `R.drawable.ic_help` (a compile-time constant, valid ID, resource present). **Falls back, does NOT crash** (per the directed question). Blast radius: every data-driven icon — all `AreenaxIcon(name=…)` call sites (tasks, achievements, notifications, admin, QR results…) and **bottom-nav tab icons** (`BottomNav.kt:82` `iconResId(tab.icon, filled=true)`); ~75 direct `R.drawable.X` references render correctly (constants inlined). Debug build unaffected.
5. **proguard-rules.pro answer (directed):** there is **no** `getIdentifier`/`R.drawable` keep rule (file read in full: only kotlinx-serialization/Retrofit/OkHttp/ZXing/Coil rules) — but the absence of the keep rule bit through R-class inlining, not through resource stripping.

## 5. ATTACK TESTS (static, Attacker-style; runtime = NOT VERIFIED, no device)

**(a) Malicious QR payloads — robust.** Full trace `a6-attack-tests-1.log`: `parseQrPayload` URL-decodes only the first `?qr=`/`&qr=` capture (stops at `&`/whitespace), then a **full-match** strict regex over a `[A-Za-z0-9_-]+` id charset → `u:123&evil=1`, `%00`, newline tails, `<img>`, nested params all fail → toast. The parsed id is only ever sent to **GET /qr/lookup**; result-card actions use **server-returned** ids (`QrSheet.kt:302-307` friend request `it.user.uid` source="QR", `:331-335` team join `it.team.id`) — QR text never feeds navigation params → no local redirect/injection gadget. Manual UID input is digit-filtered `take(12)`. Pre-auth stash (`setPendingQr`, plaintext) is re-parsed through the same strict path on consumption.
**(b) Hostile server responses — no crash path.** `safeCall` (`ApiResult.kt:55-70`) catches `RequestInFlightException`/`HttpException`/`IOException`/`Exception`; only `body["error"]` JSON string is promoted to a message (`:35-49`, non-JSON → generic fallback); `Json { ignoreUnknownKeys, explicitNulls=false }` tolerant; stale persisted user JSON → `decodeUser` try/catch → null. Server-controlled error strings render only as Compose `Text` toasts (zero WebView) → worst case cosmetic control chars/length; no injection sink.
**(c) Intent/redirection — minimal surface.** See §4: single exported launcher activity that reads no extras; no exported receivers/services/providers; CaptureActivity not externally reachable; deep-link grammar (`parseDeepLink`, `ScreenKeys.kt:109+`) exists only for notification payloads (server/pendingLink source) with a head-whitelist (`tournament:/host:/wallet/…`) → no unvalidated navigation. singleTask export is required and safe as used.
**(d) Backup extraction — real leakage path.** `allowBackup=true` + no rules + plaintext token/user (DataStore `areena-app`) → Auto Backup (cloud ≤25 MB, Google account-tied) and D2D transfer include the file by default on API 23+; `adb backup` on API 24-30 devices (user-confirmed) yields the token+PII in plaintext; on API 31+ `adb backup` is platform-restricted but cloud/D2D persists. Precise statement for a targetSdk-35 app: absence of `dataExtractionRules` = platform **defaults include app data**. → **A6-02**.
**(e) MITM posture — fail-closed L1, no L2.** Cleartext banned by default (no `usesCleartextTraffic`, system-CAs-only, no user-CA trust) → passive network MITM blocked; active MITM requires a malicious **system** CA. No pinning → cert/PKI compromise of the origin not mitigated (L2). `normalizeBaseUrl` accepting `http://` fails closed at runtime via the cleartext ban (OkHttp/NetworkSecurityPolicy refuses) → app shows NetworkError, no silent downgrade. Placeholder domain: real-origin TLS posture **NOT VERIFIED** (Q17).
**(f) Root/tamper detection — absent (RESILIENCE).** rg = 0 for su/magisk/xposed/frida/integrity checks; accepted NOTE for this app class (server-authoritative token model) → A6-06.

## 6. FINDINGS (9-field template)

### A6-01 · BLOCKER
- **ID:** A6-01 · **Severity:** BLOCKER
- **Location:** `app/src/main/java/com/areenax/nativeapp/core/ui/AreenaxIcon.kt:44-54` (reflection) + `app/proguard-rules.pro` (missing keep rule) + release build config (`build.gradle.kts:22-30`)
- **Steps to reproduce:** Build `assembleRelease` (R8 ON) → install → observe ANY screen whose icons come from `AreenaxIcon(name=…)` (bottom-nav tabs via `BottomNav.kt:82`, task/achievement/notification/QR-result icons) → all render the same `ic_help` glyph. Root: dex `LQ1/f;` (renamed `R$drawable`) has zero static fields → `R.drawable::class.java.getField(name)` always throws → catch → `R.drawable.ic_help`.
- **Expected vs actual:** Expected: Material-symbol name → correct bundled vector (as in debug). Actual: every dynamic icon = help glyph in release; NO crash (fallback ID is valid and the resource ships).
- **Root cause:** R8 (full inlining, no R keep rule in merged config) removes `R$drawable` fields as unused because code references them only via reflection with runtime-built names. Directed-check nuance: resources are NOT stripped (178/178 intact; shrinker discarded its output) — the lookup mechanism fails, not the assets.
- **Proposed minimal fix:** Replace reflection with a static `when(name)` map in `AreenaxIcon.kt` (single-file change, R8-safe, also faster), OR add `-keepclassmembers class com.areenax.nativeapp.R$drawable { public static <fields>; }` to proguard-rules.pro and rebuild. Map preferred (deterministic).
- **Regression risk:** low — icon-name set is fixed by `drawableNameFor`; map version is compile-checked.
- **Evidence:** `audit/evidence/phase2/apk-scans/a6-r8-r-drawable-reflection.log`, `apk-scans/a6-shrink-check-drawables.log`

### A6-02 · MAJOR
- **ID:** A6-02 · **Severity:** MAJOR
- **Location:** `app/src/main/java/com/areenax/nativeapp/core/session/SessionManager.kt:87-92,220` + `AndroidManifest.xml:16`
- **Steps to reproduce:** Log in → enable device backup / D2D copy to new phone → token + full user profile (incl. balance) leave the device inside the unencrypted DataStore file; or `adb backup -f a.ab com.areenax.nativeapp` on an API 24-30 device (user confirms) → extract `areena-app` → read token in plaintext.
- **Expected vs actual:** Expected: session secret unreadable at rest/extraction (MASVS-STORAGE-1 L1). Actual: plaintext bearer token + PII eligible for cloud/D2D backup and adb extraction (minSdk 24).
- **Root cause:** DataStore Preferences chosen for web-parity; no Keystore encryption layer; backup rules absent.
- **Proposed minimal fix:** (1) add `dataExtractionRules` (API 31+) + `fullBackupContent` (≤30) excluding `datastore/areena-app.preferences_pb`, cloud-backup none for that file; (2) fix-phase: wrap token in Keystore-backed encryption (e.g., EncryptedFile/Tink) when owner approves crypto dependency.
- **Regression risk:** low (rules only change backup behavior; no runtime API surface).
- **Evidence:** `audit/evidence/phase2/a6-attack-tests-2.log` (d), `apk-scans/a6-manifest-tree-release.txt`, `a6-secrets-*.log`
